# Mult — финальная сборка с автоматическим TURN
Если вы создаёте аналог игры то вот правила размещения API:
В этой сборке API Key Metered не находится в `index.html`. Браузер запрашивает TURN-настройки у серверной функции `/api/turn`, а функция получает их у Metered с помощью переменных окружения Vercel. В игре используется база Mult 2 для улучшенного соеденинения.

## Структура

- `index.html` — клиент Mult.
- `api/turn.js` — серверная функция Vercel. Не переносите её код в HTML.

## Настройка Vercel

1. Создайте отдельный Vercel-проект для Mult и загрузите в его корень `index.html` и папку `api/` из этого архива.
2. В Vercel откройте **Project → Settings → Environment Variables**.
3. Добавьте `METERED_APP_DOMAIN` — только домен приложения Metered, например `myapp.metered.live` (без `https://` и без пути).
4. Добавьте `METERED_TURN_API_KEY` — именно **TURN Credential API Key** из строки TURN Credential → Get credential → Show API Key. Не используйте общий Secret Key из Developers.
5. Для `METERED_TURN_API_KEY` выберите тип **Secret**. Для `METERED_APP_DOMAIN` подойдёт **Config**.
6. Сохраните переменные и сделайте новый Deploy / Redeploy.
7. Откройте адрес Vercel-проекта. В Mult перейдите в список комнат и нажмите **«Проверить TURN-службу»**.

После успешной проверки игрокам не нужно вводить API URL или ключ. Все клиенты, открывшие Mult с этого Vercel-домена, используют один серверный маршрут `/api/turn`.

## Важно о безопасности

- Никогда не добавляйте API Key в `index.html`, GitHub или клиентский JavaScript.
- Никогда не используйте общий Metered Secret Key в браузере. Здесь нужен отдельный Credential API Key.
- Браузер всё равно получает `iceServers` с TURN username/password: это необходимые параметры WebRTC. Скрытым остаётся основной API Key.
- В функции нет логирования API Key или полного upstream URL. Добавлено простое ограничение частоты запросов на экземпляр функции; это дополнительная мера, а не полноценная распределённая защита от злоупотреблений.
- Если ключ случайно попал в публичный репозиторий или чат, отзовите/пересоздайте его в Metered Dashboard.

## Лимит трафика

В интерфейсе Mult показано предупреждение о 500 МБ/месяц — это значение, указанное владельцем проекта для его текущего бесплатного аккаунта. Проверяйте фактическую квоту в Metered Dashboard: публичная страница Open Relay может показывать другое предложение или условия для других аккаунтов.

TURN расходуется только когда WebRTC выбрал релейный маршрут. При прямом P2P-маршруте данные идут напрямую между игроками. Если лимит TURN исчерпан, прямой P2P всё ещё может работать, но соединения, которым нужен TURN, могут перестать устанавливаться.

## Где это работает

Поскольку `/api/turn` — серверная функция, эту сборку нужно запускать с Vercel (или на другом хостинге, где аналогичная функция развёрнута по тому же пути). Если открыть `index.html` как локальный файл или разместить только на статическом GitHub Pages, серверного `/api/turn` не будет, и Mult перейдёт на встроенные ICE-серверы PeerJS.

## Рекомендации по работе мультиплеера

Рекомендуется использовать VPN для стабильного подключения TURN маршрута. Во время игры вы расходуете общественный трафик Metered в размере 500 МБ. От вас ничего не требуется, но знайте что он обновляется ежемесячно и мультиплеер станет работать на обычном P2P соединении. У игры отсуствуют реальные игровые сервера и всё завязано на обновлении браузера хост-игрока. Могут быть лаги сервера и неточности в обновлении данных сервера. Имейте это ввиду. Если вы не в России то VPN не потребуется.

## Геймплей

Если вас не интересует мульитплеер и вы просто хотите поиграть в одиночном режиме то вся информация написана в справочнике. Однако я всё равно расскажу о правилах игры в классическом режиме. Для начала держите температуру от 21.0 градуса до 22.0. В рамках этих чисел это считается нормой, однако при очень низкой температуре самолёт начнет терять двигатели и скорость. Особенно это выражено с определенными улучшениями у топливного бака. Высокую температуру тоже лучше не держать, иначе расход топлива увеличится и пожароопасность вырастит, а распространение огня в салоне станет сильнее. Регулируйте температуру с помощью термостата в конце салона рядом с кабиной пилота с помощью знаков "+"  и "-" (в зависомсти от кнопки вы повышаете или понижаете температуру на 0.5). В салоне и задней части самолёта есть ящик с инструментами. Базовые классы могут нести только 1 инструмент, поэтому с пмощью цифр выбирайте нужные инструменты (1 - изолента, 2 - сварка, 3 - швабра, 4 - молоток и 5 - отвёртка). В пути поломки появляются рандомно. Дыру можно заклеить изолентой, для этого проведите мышкой/пальцем по экрану чтобы её починить. Если где - то загорелись трубы то немедленно возьмите сварку и заделайте трубу. Также такие дыры создают взрыв который наносит немало урона, поэтому будтье осторожны. Если появилась лужа которая замедляет вас, используйте швабру. Лужи загораются при высокой температуре и огню в салоне, такие лужи можно тоже убрать, однако находясь в них вы получаете урон, протирайте полы быстрее. Окна могут разбиваться при высоком давлении и низкой температуре. Используйте молоток и почините окно. Такие окна тратят кислород и понижают температуру. И да такие поломки как дыры, разбитые окна, горящие трубы способны влиять на давление, кислород и температуру. Свет ламп также может гаснуть в зависимости от температуры и событий. Всего в салоне около 7-8 ламп и каждая из них может потухнуть в любой момент. Используйте отвёртку и соедините провода в правильном порядке. Лампы влияют лишь внешне а именно без света вы можете не увидеть дыры или другие поломки (огонь виден). Также во время грозы гаснет электричевство. Его можно починить с помощью отвёртки, для этого подойдите к электро щитку по середине и пытайтесь включить электричество пока оно не включится. После этого вам вручную понадобится починить все лмпы. Также по пути вас могут атаковать птицы и истрибитель FMRA. Если на вас летят птицы то выключите и включите двигатель, иначе у вас откажет один из двигателей и появятся поломки. С FMRA ситуация аналогична. Однако вместо выключения двигателей вам нужно сесть за штурвал в кабине пилота, а затем подождать окончания таймера. Если таймер кончился и никого не было за штурвалом то одному из двигателей будет нужен ремонт (его отключит) и возникнет много поломок. Но если кто то сидел в кабине то ему нужно увидеть инструкцию на экране и повернуть в определённную сторону (A - влево или D - вправо), затем вы увернётесь от ракеты FMRA. Самолёт равен развалюхе, поэтому следите за электричесвтом (оно также влияет на показ информации об текущих статах самолёта), за давлением, топливом и уровнем кислорода. Также в кабине пилота есть куча канистр с топлвиом. Их надо носить в хвост самолёта прямо к основному двигателю, затем залить топливо чтобы самолёт не упал на землю через время. Чтобы починить один из двигателей вам нужно пойти в правую или левую дверь. За дверью находится двигатель соотвествующей стороны. Проползите к нему по крылу самолёта, затем проведите ремонт двигателя и вернитесь обратно. Также следите за высотой. В конце матча она будет автоматически снижаться чтобы приземлиться, но если это происходит в начале после вылета или в середине пути, то это повод пойти в кабину и проверить состояние двигателей, топливо и другие статы. В игре главная валюта - FC (Flight Coins) и за неё вы можете улучшить самолёт (поменять определённые двигатели или поставить улучшения, например улучшение на размер топливного бака) или купить класс, каждый из которых применяет разные улучшения и меняет характеристики. В игре есть несколько режимов, такие как "Свободный полёт" - пролететь 3000 км со своими улучшениями и стандартными  правилами, "Экстренная ситуация" - задача та же, но у вас нету атак связанных с птицами и истрибителем FMRA, но события здесь жёстче и опаснее, а также ориентиры на пасмурную погоду, "История"- несколько глав, лор и сюжет игры. Вместо типичных привычных задач с самолётом вам надо выполнять разные миссии, пытаясь пролететь границу а также выживать в лесу на упавшем самолёте и выполнять другие задания, режим "Сетевая игра" (или же мультиплеер) в нём вы можете играть с другими игроками и выбрать любой режим (кроме Истории) и любую сложность, и режим "Бесконечный" - в котором вы не можете приземлится и вы должны лететь пока не проиграете, бонусом каждые 1000 KM вам дают бонус к получению FC. В игре есть 4 уровня слонжсоти, такие как "Очень лёгкий" - с множителем FC 0.7X, "Лёгкий" - с множителем 1X, "Нормальный" - и его множитель валюты с 1.7X и "Сложный" - имеет множитель 3X. Все они имеют соответствующие параметры игры. Двигатели может чинить только класс "Инженер".

## Общая часть кода мультиплеера

Ниже расписан каждый блок сервера который помогает запустить сетевую игру.

PeerJS	(Упрощает создание P2P-соединений): открытая библиотека для соединения клиентов. Вместо ручной библиотеки с тонной кода в проекте уже встроенна облегчённый способ работы с игроками.
WebRTC	(Передаёт данные между игроками): если PeerJS это библиотека для обработки потока данных, то WebRTC - это двигатель всего мультиплеера. Он ищет данные клиентов связанные с подключением, а затем передаёт эти данные PeerJS для обработки.
TURN (Metered) (Помогает соединяться через сложные сетевые условия): если библиотеки выше это обработчики и двигатели, то TURN это дополнение к PeerJS для обхода региональных ограничений (включая и ограничения провайдеров). Он шифрует данные клиентов (игроков) а затем стабилизирует задержку при ограничениях. Однако он использует трафик TURN, это не влияет на работу клиентов игроков, но влияет на сервера игры. Но этот метод создаёт отличный маршрут для игры.
PeerJS Server (Помогает игрокам находить друг друга): не путать с библиотекой PeerJS. Это часть самого PeerJS, но он не выполняет работу с анализом данных клиентов. Вместо этого он помогает подлкчюиться по коду в комнате с помощью списка комнат.
JavaScript (Управляет комнатами, игроками и синхронизацией): улучшает задержку в мультиплеере. Также похож на PeerJS Server, но задача у него: оптимиизировать код под сетевую игру.

Создание комнаты. Хост получает шестизначный код, а PeerJS регистрирует его сетевой идентификатор.

Подключение. Остальные игроки вводят код и устанавливают соединение с хостом.

Обмен данными. Игроки передают хосту свои действия, а хост рассылает остальным обновления состояния игры.

Синхронизация. В коде предусмотрены снимки состояния (snapshots), интерполяция движения и повторная синхронизация, если данные перестали поступать.
